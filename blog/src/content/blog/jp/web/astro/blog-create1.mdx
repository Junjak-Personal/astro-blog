## はじめに  
  
開発中の問題を解決しても、きちんと記録しないせいですぐに忘れてしまう、という悪い癖がある。  
それに、開発者なら自分の開発ブログくらい持っていたいという気持ちもあり、  
開発ブログを作って記録を整理すれば、忘れにくくなるうえに記録も残って一石二鳥ではないか。そんな思いでブログを作ることにした。  
  
### 最初の挑戦  
  
最初に作ろうとしたのは2022年7月ごろで、そのときも動機は先ほどと同じだった。  
ただ、仕事が忙しいうえに会社との衝突もあり、精神的に余裕のない時期だった。大まかなレイアウトだけ作って、そのまま立ち消えになってしまった。  
プロジェクト一覧にもあるはずだが、未完成のままだ。  
  
  
  
そのとき選んだのは、まだbetaだったnuxt3のcontent。  
ローカルにcontentとして保存したマークダウンを少し見栄えよく加工し、ssgのサイトにするつもりだった。  
  
こちらが当時作った[未完成のサイト](https://jundev-blog.netlify.app/)。20〜30時間ほどかけたところで中断した。

### 2回目の挑戦（現在）

## 技術スタックを選ぶ  
  
ブログを作るなら、mediumやvelog、tistoryといった既存のプラットフォームより、自分で一つずつ作っていきたかった。  
  
購読しているIT系YouTuberのfireshipがAstroを絶賛していて、以前から気になっていた。技術検証も兼ねてブログをAstroで作ってはどうかと思い、まず試してみた。  
  
### Astro  
  
まずAstroはドキュメントが充実していて、チュートリアルもよくできていると感じた。この二つが気に入った。  
  
最初のブログ作りで使ったnuxt contentと比べても、Astroはより具体的なAPIと使いやすい仕組みを提供していた。進歩した印象が強く、Astroを使うことに決めた。  
もう一つの長所は[Island](https://docs.astro.build/ko/concepts/islands/)構造で、VueやReact、Svelteなどで作ったコンポーネントをastroのページに追加できること。  
長い間Vueばかり使ってきて、今はReactを試している。Reactを使いつつ、検証用にほかのフレームワークも差し込める点が魅力だった。  
  
  
  
Astroの使い方や使ってみた感想は、別の記事にまとめる予定だ。  
  
### CSS Library  
  
CSS Libraryには、最近React界隈で人気のShadcn-uiを使いたかった。  
コンポーネントを見てみると、欲しいデザインとは少し違った。そこでawesome-shadcnというものを探してみると、  
ユーザーがshadcn-uiを自由にカスタマイズして公開しているライブラリーが、かなりたくさんあった。  
  
  
  
その中で[Nyxb-UI](https://nyxbui.design/)を見つけた。アニメーション付きのコンポーネントが多く、ブログにぴったりだと思って採用した。  
Shadn-cnをベースにしたライブラリーなので、レイアウトやドキュメントの形式はshadcnと同じで、  
shadcnにあるコンポーネントは標準でそろい、さらに独自のコンポーネントも追加されていた。

## 次の目標

そこで、追加で開発する内容も含め、次の目標を決めた。  
  
- レイアウトを整える  
  - Headerの不具合修正（Shadcn Tabsを使っているが、なぜか反応が遅い）  
  - Footerを追加  
  - レスポンシブ対応を整える  
- ページルーティングの不具合を調べて解決する  
- Homeに要素を追加
